# Project Progress Demo & Review (Deliverable 3)

## Overview

The **Project Progress Demo & Review** is a milestone where teams demonstrate the current state of their Big Project after completing **Deliverable 2: Project Development Checkpoint**.

The purpose of this milestone is to evaluate the progress made from the initial implementation toward a working project and provide a checkpoint before the final project submission.

At this stage, teams should demonstrate that they have started transforming their project plan into an implemented data science workflow and are building the foundation required for the final project.

Teams should demonstrate progress in areas including, but not limited to:

- Understanding of the engineering problem and project objectives.
- Data acquisition and preparation.
- Data analysis and visualization.
- Analytical methods or modelling approaches.
- Software implementation or project prototype development.
- Initial results, insights, or outputs.

The goal of this demo is **not to present a finished project**. Instead, teams should demonstrate meaningful technical progress, show the current functionality of their project, and explain how the remaining work will be completed before the final submission.

# Demo Format

## Presentation and Live Demonstration (10 minutes)

The majority of the presentation should focus on demonstrating the current project implementation.

A recommended structure is:

---

## 1. Project Context and Progress Summary (1–2 minutes)

Briefly introduce:

- Engineering problem.
- Project objective.
- Current project status.
- Major progress since Deliverable 2.

Avoid repeating the full project proposal. Focus on what has changed and what has been implemented.

---

## 2. Technical Workflow Overview (2–3 minutes)

Explain the current workflow, including but not limited to:

- Data sources used.
- Data preparation steps.
- Analysis pipeline.
- Models or analytical methods.
- Software/application components.

Teams should explain how their implementation connects to the original engineering problem.

---

## 3. Live Demonstration (5 minutes)

The live demonstration is the **most important part** of this milestone.

Teams should demonstrate working components of their project, including but not limited to:

- Data processing pipeline.
- Exploratory analysis workflow.
- Visualizations or dashboards.
- Machine learning model.
- Prediction or analysis results.
- Prototype application.
- Deployed application, dashboard, or other accessible interface (if available).
- Other meaningful project functionality.

A deployed application, dashboard, or interactive tool that allows the teaching team to directly access and evaluate the project is **strongly encouraged**. This demonstrates a higher level of project maturity.

The demonstration should show that the current implementation can be executed and produces meaningful outputs.

Examples include:

- Running a notebook.
- Running an application locally.
- Showing a deployed dashboard/application.
- Executing a data pipeline.
- Demonstrating generated results.

Teams should prepare their demo environment before the presentation.

A **live demonstration is strongly preferred**. If a live demonstration is not possible, teams may provide a recorded demonstration. However, a recorded demo will not provide the same level of evidence as a live demonstration because the teaching team cannot interact with or ask questions about the workflow during execution.

---

## 4. Remaining Work Toward Final Submission (1 minute)

Briefly discuss:

- Remaining technical tasks.
- Planned improvements.
- Current challenges.
- Expected final project outcomes.
